# Internationalisation

Holds for any UI framework and for user-facing text in tools.

### BP-I18N-001: Route every user-visible string through a message key

Buttons, headings, body copy, errors, empty and loading states, placeholders, titles, accessible names and schema messages all come from message keys, even in a single-language build.
Why: a second locale is then a new message file.
Check: lint

### BP-I18N-002: Keep one locale list

One list of supported locales feeds routing, services, prebuilt sets and generated indexes; the default is its first entry and no locale string is hard-coded elsewhere.
Why: adding a locale is one edit.
Check: review

### BP-I18N-003: Validate the locale at entry

Validate and normalise the locale where a request or command enters; fall back to the default everywhere else.
Why: an unknown locale is rejected once and handled consistently.
Check: review

### BP-I18N-004: Pass the locale explicitly

The locale is an explicit argument of every cached read and of every handler that runs outside a route context.
Why: it is then in every cache key and never read from ambient state.
Check: review

### BP-I18N-005: Resolve messages and content in one locale

Within one scope, messages and content are resolved with the same locale value.
Why: mixed-locale screens are confusing and look broken.
Check: review

### BP-I18N-006: Use message syntax for plurals and selection

Write plurals and selections in the message format (`{count, plural, one {# item} other {# items}}`), never as conditionals in code.
Why: plural rules differ by language.
Check: review

### BP-I18N-007: Translate whole sentences

One key holds one full sentence with named arguments; never concatenate translated fragments.
Why: word order differs by language.
Check: review

### BP-I18N-008: Put markup in messages through tag callbacks

Rich text in a message uses tags rendered by callbacks, never raw HTML injected from a message.
Why: messages are data; raw HTML from them is an injection path.
Check: review

### BP-I18N-009: Type message keys and locales

Message keys and the locale type are checked by the compiler.
Why: a missing key fails the build instead of rendering a key.
Check: review

### BP-I18N-010: Format numbers, dates and units by locale

Format numbers, dates, durations and units with locale-aware formatters.
Why: separators, order and units differ by locale.
Check: review

### BP-I18N-011: Take fallbacks from messages too

Never write `text ?? 'Default'` with literal copy; fallbacks come from messages too.
Why: a literal fallback shows one language inside another.
Check: review

### BP-I18N-012: Treat content language separately from interface messages

Content (titles, descriptions, metadata) is fetched in the right language at its source; a content-language bug is fixed in the source read, not with message keys.
Why: message files cover only the strings the code owns.
Check: review

### BP-I18N-013: Set the language on every multilingual read

When a source is multilingual, every read sets the language explicitly, including reads by id; one request never mixes two locales; related ids are resolved against the rendering locale.
Why: an unscoped read silently returns the default language or swaps related items.
Check: review

### BP-I18N-014: Keep the locale in links and requests

Generated links and data requests carry the active locale; a language switcher links to each translation's own path.
Why: navigation never drops the user into another language.
Check: review

### BP-I18N-015: Use only locale-aware navigation helpers

Links and redirects use the locale-aware helpers; the locale-unaware versions are banned outside the one link component.
Why: unaware helpers drop or misread the locale prefix.
Check: review

### BP-I18N-016: Advertise only translations that exist

Alternate-language links and generated indexes list a locale only where content exists in it.
Why: advertising missing translations sends users and clients to errors.
Check: test

### BP-I18N-017: Keep endpoints out of locale routing

Locale routing skips endpoints, change notifications, telemetry and static assets.
Why: a locale redirect drops a request body and silently breaks the endpoint.
Check: test

### BP-I18N-018: Test long translations and right-to-left layout

Exercise screens with the longest translations and a right-to-left locale.
Why: layouts built for one language clip in others.
Check: review
